# Selecting an agent

This repository carries a **2026-09-15 snapshot** of 120 local specialist profiles, plus the two independent starter roles: [`delivery_worker`](../../agents/delivery_worker.toml) and [`delivery_reviewer`](../../agents/delivery_reviewer.toml). The snapshot records the local catalog at export time; it is not a claim about a universal or live installation.

Every included specialist declares `gpt-5.6-terra` with `high` reasoning. Sandbox mode is profile-specific; [`catalog.json`](../../agents/catalog.json) records it for each profile. `default`, `explorer`, and `worker` have no explicit local sandbox declaration, so their catalog value is `null`.

Use a specialist only when the task has a clear, independent boundary. Small, known-scope work stays with the root agent. The root retains task ownership, integration, and approval decisions; adding a specialist does not create an every-phase delegation rule.

| Task shape | Start with | Consider when the scope requires it |
| --- | --- | --- |
| Map an unfamiliar codebase before changing it | [`code-mapper`](../../agents/specialists/code-mapper.toml) | [`explorer`](../../agents/specialists/explorer.toml) |

| Fix or build a React surface | [`react-specialist`](../../agents/specialists/react-specialist.toml) | [`frontend-developer`](../../agents/specialists/frontend-developer.toml), [`ui-fixer`](../../agents/specialists/ui-fixer.toml) |

For example, an unfamiliar service defect can start with [`code-mapper`](../../agents/specialists/code-mapper.toml) to identify the execution path, then use [`debugger`](../../agents/specialists/debugger.toml) only if there is a reproducible runtime failure. A narrow controller edit with clear tests normally remains a root-owned task.

## Role, model, skill, and tool are separate choices

- A **role** supplies a focused responsibility and operating instructions. Select it from the task boundary, such as [`database-optimizer`](../../agents/specialists/database-optimizer.toml) for a query-plan issue.
- A **model** supplies the capability and reasoning setting. This exported specialist snapshot consistently uses Terra/high; the root session can use a different model without changing the selected role.
- A **skill** supplies a reusable workflow or domain procedure. Use one only when its trigger applies; it does not outrank system, developer, or user instructions.
- A **tool** performs an action, such as reading files, running tests, or interacting with a browser. Tool use remains bounded by the active task and permissions.

Choose the role first, then apply any relevant skill and the smallest set of tools needed to produce reviewable evidence. The two starter roles remain available for simple delivery and independent review when a specialized profile would add no value.
